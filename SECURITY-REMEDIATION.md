# Исправления по аудиту 29.10.2026

Исправления внесены в исходники RxLauncher 3.12.0. Ранее собранные EXE и развёрнутый API не обновляются автоматически.

| Пункты аудита | Изменение |
|---|---|
| RX-01 | Ограниченный NBT-парсер: 32 МБ входа/распакованных данных, 400 000 элементов, глубина 64, проверка длины и завершающих байтов. Чтение `level.dat` выполняется в worker с ограничением JS heap и таймаутом. `servers.dat` проверяется перед editable-парсером mcnbt. |
| RX-02, RX-03 | Метаданные JAR/ZIP читаются выборочно без распаковки. Имя иконки относится только к записи внутри архива; повреждённые данные возвращают безопасный результат. Ограничены размер, число записей, время чтения, PNG и схемы зависимостей. Ошибка одного мода/ресурспака не останавливает список. |
| RX-04 | Релизный gate проверяет ожидаемого издателя, подписи, timestamp и собственные Setup/Uninstall. Для выпуска нужен действующий доверенный сертификат; см. SIGNING.md. Подписанная сборка на этом компьютере не создана. |
| RX-05 | Discord OAuth использует nonce-cookie с HttpOnly/Secure/SameSite=Lax, привязку flow и signup ticket к браузеру, TTL, одноразовость и проверку исходной сессии при link. |
| RX-06, RX-08 | Java выбирается из актуальной major-ветки Adoptium, архив проверяется по SHA-256 и размеру. Проверяются все файлы сохранённого runtime, установка выполняется через staging с откатом. Authlib 1.2.8 закреплён по URL, размеру и SHA-256 и проверяется перед использованием. |
| RX-07 | Restore предварительно проверяет все операции, допустимую цель и тип части, отклоняет обходы и junction/symlink. Очистка старого unpacked cache также не проходит через ссылки. |
| RX-09 | Исправлено определение TAR.GZ; ZIP/TAR предварительно валидируются, распаковка выполняется в ограниченном worker. Отдельная потоковая проверка ограничивает служебные PAX/GNU-заголовки TAR до накопления библиотекой в памяти. |
| RX-10 | Посторонние файлы и повреждённые ZIP пропускаются при перечислении ресурспаков. |
| RX-11 | Bootstrap не повышает существующий обычный аккаунт по совпадению ника. При конфликте API отказывается запускаться с понятным сообщением. |
| RX-12 | Частично: NBT и распаковка вынесены из renderer через проверяемый IPC в workers основного процесса. Полный sandbox интерфейса ещё не включён: изолированный preload по-прежнему использует Node для других функций. |

## Проверки

Из корня проекта:

```powershell
node tests/run.cjs
node --no-warnings server/api/test.js
node_modules/electron/dist/electron.exe tests/electronUiSmoke.js
node_modules/electron/dist/electron.exe tests/electronWorkerSmoke.cjs
```

Новые сценарии содержатся в `securityRemediation.test.js`, `apiSecurityRemediation.test.js`, `workerFileSafety.test.js` и `electronWorkerSmoke.cjs`. Они используют временные данные; ответ Discord подменён только в штатном тестовом режиме. Отдельная проверка Electron подтверждает вызовы из isolated preload, workers из ASAR, запрет внешней папки назначения и чужого окна.

## Развёртывание и ограничения

- Каталог `server/` исключён из Git существующим `.gitignore`. Изменения `server/api/server.js` и `server/api/test.js` нужно сохранить и перенести на API-сервер отдельно; обычный commit их не включит. Реальный VPS не обновлялся.
- Для OAuth нужен HTTPS: cookie намеренно Secure. Живой Discord-вход и перенос между двумя подписанными версиями требуют проверки в окружении выпуска.
- Старый автоматически скачанный Java runtime без контрольной записи считается непроверенным и скачивается заново. В офлайне работает ранее проверенный runtime. Путь к Java, вручную выбранный пользователем, остаётся его явным выбором.
- Контрольная запись runtime защищает от повреждения и незамеченной подмены файлов, но не от локального атакующего, способного одновременно переписать и файлы, и контрольную запись. Доверие исходному архиву основано на HTTPS-метаданных Adoptium и SHA-256; отдельная GPG-проверка не добавлена.
- Лимиты worker_threads относятся к JS heap и времени задачи, а не к полноценному системному sandbox или строгому лимиту всей памяти процесса. Отдельная миграция оставшегося Node-кода из preload необходима для `sandbox: true`.
- В TAR допускаются ограниченные служебные заголовки (до 64 КиБ каждый и 2 МиБ суммарно). PAX-переопределение размера файла отклоняется; стандартные TAR.GZ и PAX-пути проверены.
- Проверка зависимостей и тесты не доказывают отсутствие всех будущих или неизвестных уязвимостей. Linux/macOS, реальные игровые установки и обновление production-сервера в этой среде не проверялись.

Границы защит соответствуют описанию [sandbox Electron](https://www.electronjs.org/docs/latest/tutorial/sandbox) и [resourceLimits Node.js workers](https://nodejs.org/api/worker_threads.html#new-workerfilename-options): worker не заменяет системную песочницу, а sandboxed preload требует переноса прямого доступа к Node в основной процесс через IPC.
